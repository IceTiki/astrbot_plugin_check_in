# AstrBot 习惯打卡 v1.9.4

## v1.9.4 修复 · 月历得分可视化

- 每个任务格的填充比例现在按该任务的实际得分百分比绘制，而不是只看打卡次数是否达到目标；按时满分实心，迟到扣分会显示为对应比例的半填。
- 默认八项任务改为四列两行，方块更大；自定义任务较多时自动调整行数和方块尺寸。
- 本月完成度百分比更醒目，并增加更粗的总进度条；每日进度条也加粗。
- 空框使用高对比边框，停用／未来任务使用低对比淡框和短横线，便于区分。
- 本次只修改月历可视化，不改变计分规则、数据库结构或历史记录。


基于 v1.9.1 更新默认任务模板、调试权限和管理员用户管理；保留统一命令体系和 Metro 图片帮助。**数据库保持 SQLite，无需重置账户或历史打卡数据。**

## v1.9.3 新增 · 默认任务与用户管理

- 新用户默认任务：睡觉 23:30、起床 08:00、早餐 09:00、午餐 12:00、晚餐 18:00、运动不限时、规划待办 10:00、完成待办 22:00；均为每天 1 次、权重 1；限时任务半衰期 60 分钟；凌晨 04:00 换日。
- 普通用户可以更名／重名合并／彻底删除自己的任务；管理员可用账户 ID 对其他用户执行相同操作。
- `/打卡 调试 用户列表` 展示账户 ID、群昵称及身份别名。
- `/打卡 调试 删除用户 账户ID` 两阶段确认后删除该账户及合并来源账户、个人任务、记录、可识别的旧会话记录和身份映射。不能删除当前操作者自己的账户。
- 所有危险操作仍须预览、五分钟确认和操作前 SQLite 备份。

## v1.9.1 新增 · 安全调试任务（行为被 v1.9.3 扩展）

普通用户可以调试自己的任务；管理员额外拥有跨用户管理功能。这里的管理员指 AstrBot 配置中的管理员，不是单纯的 QQ 群管理员。

- `/打卡 调试`：展示调试命令和风险说明。
- `/打卡 调试 更名 旧名称 新名称`：预览更名。如新名称已存在，预览同名合并。
- `/打卡 调试 彻底删除 任务名称`：预览当前个人账户下删除任务定义、版本规则、每日计数和全部打卡事件。
- 预览后机器人发出随机 8 位确认码，有效期 5 分钟。必须再次发送 **完整确认指令**，否则绝不执行。
- 执行前自动产生一致的 SQLite 备份，保存在 AstrBot 数据目录的 `backups/astrbot_plugin_daka/maintenance/`。旧版本快照与升级备份不会被自动清理，**因此“彻底删除”指当前在线数据库的个人任务数据，不代表擦除所有备份文件**。
- 所有涉及的表在同一 SQLite 事务中更改；预览后数据变化则取消操作，需重新生成确认码。
- 更名（目标名不存在）一次性同步修改 `habits`、`habit_rules`、`records` 和 `checkin_events`，保留事件时间及历史计分版本。
- 同名合并（目标名存在）保留 **目标名称的现有设置与启用状态**；目标规则存在前的旧任务规则会迁入。同日累计打卡次数相加，但最多计入目标任务当日规定次数；仍会保留两项的全部原始事件及其时间，因此历史评分可能变化。原名称的定义、规则和日记录在合并后删除。
- 历史数据只作用于当前个人 `person:` 命名空间。其他账号、旧群级遗留记录及数据库快照不受影响。删除默认任务也不会因为再次重启被自动恢复（已有 `score_profiles`）。
- 可以通过操作前快照手动恢复，但没有提供聊天内撤销；恢复时需谨慎处理备份创建后发生的新记录。

## v1.9.0 原有命令体系（保持不变）

- 日常仅支持 `/打卡 习惯名称`，每次只增加 **1 次**。移除编号打卡、`+2` 等批量打卡、普通打卡附带历史日期及批量补签。
- 任务新增／修改／恢复统一为 `/打卡 任务 目标 名称 次数`。任务删除是软删除，历史记录保留。
- 查询、补签、清除统一放到 `/打卡 记录 ...`；计分与时间设置统一为 `/打卡 任务 ...`。
- 月历、社交、账户、群提醒按「月历」「好友」「账户」「群设置」分组。
- 个人默认显示在 `/打卡 视图` 下设置：今日／月历／帮助图片或文字、快捷操作类型。
- `/打卡 帮助` 默认发送**完整命令示例的 Metro 图片帮助**，和纯文字版共用单份 `help_content.py` 数据。缺少 Pillow/中文字体或图片发送失败时拆分发送完整文字帮助。
- 个人默认视图按账号统一：相同账号在群聊和私聊共用偏好，不影响其他账号；迁移旧的会话级显示偏好时保留旧行，不清空原值。
- QQ 按钮与文字链接均发送新命令，移除 `+1` 形式；定时提醒文字也使用新命令。
- 删除旧命令解析入口，而非永久保留历史别名；曾创建的同名任务和历史记录依然留在数据库。
- **计分方式仍为 v1.7 的连续半衰期，凌晨 04:00 换日；不改历史得分或历史记录。**

## 行为说明

1. `/打卡` 查看今日状态。`/打卡 阅读` 一次记录 1 次（每次打卡只增加 1 次）。
2. `/打卡 任务 目标 运动 3`：
   - 首次创建：每天 3 次，权重默认 1。
   - 当前已启用：更新每天目标次数。
   - 历史中存在但已停用：恢复并更新目标次数，历史打卡记录保留。
3. `/打卡 任务 删除 运动` 停用习惯，不删除原有 SQLite 记录。
4. `/打卡 任务 时间 睡觉 23:30 60`：最佳 23:30，半衰期 60 分钟；`时间 运动 关闭` 关闭限时计分。更新规则从今天的打卡日生效，旧日期仍保留历史规则。
5. `/打卡 记录 补签 ...` 每次只有 1 次，日期最多向前 14 天（可改配置）。限时任务必须给出真实完成时间。
6. `/打卡 记录 清除 睡觉` 清除这一天该任务的**全部记录**，不是减少一次。
7. 新用户不能创建与系统命令冲突的任务名；纯数字任务名也不允许，以免与旧编号模式混淆。
8. 从旧 v1.8 升级后，旧命令（例如 `/打卡 添加`、`/打卡 月历视图`、`/打卡 交互`）不再受理，统一提示参考新帮助。
9. QQ 官方机器人图片和快捷按钮有可能分别发送两条消息。QQ 客户端是否成功展示取决于其接口和权限，不保证一定支持图片和快捷按钮。
10. 完整帮助图片约 1080×4994；QQ 压缩后可双击放大。要纯文字请执行 `/打卡 视图 帮助 文字`。

## 个人默认视图与数据库迁移

数据库文件仍是 `data/plugin_data/astrbot_plugin_daka/checkin.sqlite3`。

首次升级旧数据库时会创建 SQLite 快照（当前代码在 `PRAGMA user_version < 10901` 时生成 `pre-1.9.1-*.sqlite3`）。保留所有旧表，并仅对 `ui_preferences` 表追加可空列 `help_view_mode`，不创建独立数据库。

使用个人账户的 `scope` + 固定 `origin=__person__` 存储新偏好，原来的 `scope` + 群聊/私聊 `origin` 行保留供回滚。如果群聊与私聊保存了不同的偏好，**首次使用 v1.9 的会话**会决定迁移的初始值，之后同步。

在个人账户合并之前已分别保存的偏好可能随账户合并采用目标账户的默认值；**数据本身不会被清空**。如果需更改，只需重新发送 `/打卡 视图` 设置。

## 部署说明：Debian + Docker

既有服务器目录 `/opt/services/astrbot`、容器 `astrbot`。

**不要先在 AstrBot WebUI 卸载旧插件**。WebUI 卸载可能连 `plugin_data` 一并删除。

推荐先运行配套更新脚本 `--check-only` 检查安装目录与 Docker bind mount，确认后停止容器、备份源码及 `plugin_data`、只更换插件代码并启动容器：

```bash
cd /opt/services/astrbot
python3 astrbot_plugin_daka/update_source.py astrbot_plugin_daka_v1.9.4.zip --check-only
python3 astrbot_plugin_daka/update_source.py astrbot_plugin_daka_v1.9.4.zip
docker logs --since 3m --tail=150 astrbot
```

可在 AstrBot 插件设置中配置 `help_display_mode=image/text`，用户也可通过 `/打卡 视图 帮助 图片|文字` 分别保存个人偏好。

**中文图片字体**：建议 Docker 环境安装 Noto Sans CJK（例如 Debian 的 `fonts-noto-cjk`），否则帮助自动回退完整文字版。Pillow>=10 必需。

## 旧用户一次性默认任务迁移（Debian）

插件升级后，新注册账户使用 v1.9.4 的新默认模板。若要把旧账户也统一成新模板，请在 Debian 上先执行只读预览，再显式执行迁移脚本。脚本会删除所有 scope 中「工作一小时」的任务、规则、每日记录和事件；其他任务的历史记录会保留。八个新默认任务的目标、时间、权重、启用状态和排序从当前业务日统一生效；自定义任务的目标、权重、时间和启用状态保留，只将排序放到默认任务之后。旧版「早睡／早起」若能无冲突改名会转为「睡觉／起床」；若两种名称都已有数据，则旧名称保留为停用任务，避免覆盖历史。

```bash
# 先预览，不改数据库
python3 astrbot_plugin_daka/migrate_defaults_v193.py --db /opt/services/astrbot/data/plugin_data/astrbot_plugin_daka/checkin.sqlite3

# 确认路径和预计删除内容后才实际执行
python3 astrbot_plugin_daka/migrate_defaults_v193.py --db /opt/services/astrbot/data/plugin_data/astrbot_plugin_daka/checkin.sqlite3 --apply

docker restart astrbot
```

脚本会在数据库所在插件数据目录的 `backups/astrbot_plugin_daka/migration/` 下，通过 SQLite backup API 生成一致性备份。若你的数据库位于其他路径，请以实际路径替换 `--db`。该操作会影响数据库中所有用户／scope，执行前务必核对预览。
