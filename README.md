# AstrBot 习惯打卡 v1.7.0

本版本从 v1.6.0 的「宽限后阶梯减半」切换为**最佳时间一到就开始连续指数半衰期衰减**。
保留 QQ 官方机器人按钮/文字链、月历图片、QQ 群与私聊统一账户、准确打卡时间、任务权重、凌晨 04:00 换日和补签。
插件名、容器名及数据目录不改变，不需要 LLM、不新增服务。

## 新时间公式（重要）

- `best_time`：最佳完成时间 `T`，达到或提前完成得满分。
- 数据库里的 `delay_minutes` **保持原字段名不变**，但从 v1.7.0 起含义为半衰期 `H`（分钟）；无须改数据库列。
- `minutes_late = max(0, (occurred_at - best_time).total_seconds() / 60)`。
- **时间分数系数 = `2 ** (-minutes_late / H)`**。
- 计分从最佳时间之后立即平滑下降，**没有原来的满分宽限窗口**。
- `H=30` 时，迟到 30 分钟降到原分数的 50%，60 分钟为 25%，90 分钟为 12.5%。
- 打卡时间存档之后不会持续扣分，得分基于保存的实际发生时间。

| 睡觉最佳时间 23:30、H=30分 | 得分系数 |
|---|---:|
| 23:30及之前 | 100% |
| 23:35 | 89.1% |
| 23:40 | 79.4% |
| 23:45 | 70.7% |
| 次日00:00 | 50.0% |
| 次日00:15 | 35.4% |
| 次日00:30 | 25.0% |

规则仅改变**按时完成的得分系数**，不改变“打过卡”这一客观状态：迟到任务仍能显示为已完成，但得分低于满分。

## 默认任务与目标

| 任务 | 每日次数 | 最佳时间 | 半衰期 H | 权重 |
|---|---:|---|---:|---:|
| 睡觉 | 1 | 23:30 | 30分钟 | 1 |
| 起床 | 1 | 08:00 | 30分钟 | 1 |
| 早餐 | 1 | 09:00 | 30分钟 | 1 |
| 午餐 | 1 | 12:00 | 30分钟 | 1 |
| 晚餐 | 1 | 18:00 | 30分钟 | 1 |
| 运动 | 1 | 不限时间 | 无 | 1 |
| 工作一小时 | 3 | 不限时间 | 无 | 1 |

- 每项任务的“整项权重”仍默认为 1。工作一小时 3 次合起来最多得 1 分；设置时间要求后，每次独立按其打卡时间计算时间系数再均分。
- 任务权重为 0 仍可打卡、显示记录与单任务月历，不影响总分分子和分母。
- 每日总完成度 = 当天计分任务得分之和 / 这些任务的权重之和；月历/月度完成度按已计入打卡日累计。月度包括当前打卡日及尚未打卡而已启用的日期，不计未来日期。
- 多次任务超过目标次数后，不额外增加打卡次数和得分，也不覆盖过去记录的完成时间。

## 打卡日期与时区

- 默认时区：`Asia/Shanghai`，可在 AstrBot 插件配置中调整。
- 打卡日 D 的范围 `[D 04:00:00, D+1 04:00:00)`。
- 睡觉 23:30，实际次日00:10，仍属于前一天；若最佳时间是 00:00～03:59，则指定的是打卡日的“次日凌晨”。
- 不需要清空 SQLite 表或执行重置任务：换日时通过日期划分记录。

```text

/打卡 工作一小时 +1
/打卡 规则
/打卡 设置
/打卡 设置 睡觉
/打卡 半衰期 睡觉 30
/打卡 半衰期 起床 45
/打卡 时间 睡觉 23:30 30
/打卡 最佳 睡觉 23:45
/打卡 延迟 睡觉 30
/打卡 时间 运动 关闭
/打卡 权重 运动 0
/打卡 目标 工作一小时 3
/打卡 记录
/打卡 月历
/打卡 月历 睡觉
/打卡 补签 睡觉 昨天 23:50
/打卡 撤销 睡觉
/打卡 交互 按钮
/打卡 交互 文字链
/打卡 诊断
```

`/打卡 半衰期 任务 H`：修改半衰期，范围为 **1～1440 分钟**。
`/打卡 时间 任务 HH:MM H`：同时设置最佳时间和半衰期。
`/打卡 延迟 任务 H`：为了兼容旧命令继续受理，但在**新日期规则中参数也表示半衰期**；不再表示延迟宽限。
更改规则从**当前打卡日**生效并重新计算当天已打卡任务；已结束的历史日期不变。

## 与旧版兼容及迁移

1. 数据库仍保留原 `habit_rules.delay_minutes` 列，含义从 **v1.7.0 新规则起**转为半衰期；用户之前设置的30、45、60分钟等数值原样保留。
2. 新版本首启时，为已有个人账户写入**当前打卡日**的 `model=half_life` 规则版本，记录一次性的 `score_engine_migrations` 标记。
3. v1.6 已结束的日期保留原 `model=weighted` 阶梯公式；更早旧版本 `model=legacy` 依旧使用不追溯扣分的旧次数语义。
4. 新账户/新任务/用户手动更改时间和权重都使用半衰期模型。
5. 今天的记录可能因从阶梯计分改成半衰期而变化，这是预期行为；昨天及更早日的历史分数不变。
6. 不修改之前的打卡次数、事件真实时间、QQ 身份映射、隐私、群成员映射、权重和启用状态。
7. 首启时在数据库迁移前做 `pre-1.7-时间戳.sqlite3` 备份（如果数据库 user_version < 10700），不会伪造旧时间。

## 安全安装和升级（Debian + Docker）

当前服务器路径 `/opt/services/astrbot`，Docker 容器名 `astrbot`。
**请勿先去 WebUI 卸载原插件**：以前卸载过程曾删除 `plugin_data` 数据库。

将下面文件传到 Debian 的 `/opt/services/astrbot/`：

- `astrbot_plugin_daka_v1.7.0.zip`
- `update_astrbot_daka_v1.7.0.py`

执行：

```bash
cd /opt/services/astrbot
python3 update_astrbot_daka_v1.7.0.py astrbot_plugin_daka_v1.7.0.zip --check-only
python3 update_astrbot_daka_v1.7.0.py astrbot_plugin_daka_v1.7.0.zip
docker logs --since 3m --tail=150 astrbot
```

更新脚本首先校验压缩包并检查数据挂载路径；更新时先短暂停掉 `astrbot` 容器，备份源码及 `plugin_data`，只替换插件源码，成功后重启。失败时尽力自动恢复旧源码。不更改 Docker Compose、网络或其他服务。

**特别提醒：** 若数据库 v1.6 仍在使用且首启迁移已执行，简单切回 v1.6 代码并不能自动回退新版规则记录。需要回滚时应先停容器、恢复**更新前**的数据库和源码备份；不要直接 WebUI 卸载。
